# ADR-0001: 合成データ生成・取り込み・画面を TypeScript で統一して実装する

- ステータス: 採用
- 日付: 2026-10-12
- 関連: Notion 要件定義(REQ-001〜REQ-020)、基本設計「システム構成」、ADR-0002

## コンテキスト

異なる情報源のイベントを共通の時間軸に並べる PoC を、1〜2か月・1〜2名で作る。
必要な部品は、合成データの生成(REQ-009)、ファイルの取り込みと共通イベント形式への変換(REQ-001〜004)、
Web のタイムライン画面(REQ-005〜008, 010〜020)。
共通イベント形式は取り込みと画面の両方が扱うため、定義のずれが不具合に直結する。
開発は devContainer 内で行い、依存の取得先は npm・PyPI・NuGet に限られる。Node.js は lefthook 用に導入済み。

### 検討した選択肢

| 案 | 却下理由 |
|---|---|
| Python(生成・取り込み)+ TypeScript(画面) | データ処理は書きやすいが、言語・パッケージ管理・lint/test が2系統になり、少人数・短期では負担が大きい。共通イベント形式の型を2言語で二重に定義することになる |
| Python のみ(Streamlit など) | 最速で作れるが、イベントを選んで関連イベントに絞る、大量の行を滑らかにスクロールするといった操作の作り込みが難しい(REQ-007, REQ-005)。静的サイトとして公開できない(ADR-0002) |

## 決定

**合成データ生成・取り込み CLI・Web 画面をすべて TypeScript(Node.js)で実装し、npm workspaces の1リポジトリで管理する。**

判断の根拠:

1. **共通イベント形式の型を1か所で定義し、全部品で共有できる。** 取り込みが書き出す JSON と、画面が読む JSON のずれを型検査で検出できる。
2. **ツールチェーンが1系統で済む。** Node.js は導入済みで、依存は npm だけから取得できる(ファイアウォールの許可ドメインを増やさなくてよい)。
3. **画面の操作性を作り込める。** React の部品と仮想スクロールで、1万件規模の一覧と関連イベントの絞り込みを実現できる。

## 結果

- 画面は React + Vite、情報源の定義ファイルは YAML(`yaml` で読み、`zod` で検証)、公開先(Cloudflare Pages)へのデプロイは `wrangler` を使う。
- 実行は `tsx` で TypeScript を直接動かす。
- データ処理のライブラリは Python ほど豊富ではない。時刻の解析は Luxon に寄せ、足りなければ個別に検討する。
- lint/test のジョブを CI に追加する作業が発生する(ESLint・Vitest を想定)。
- PoC 後に API を作る場合は Hono を使う。PoC 後に DB を使う場合、その選定は別の ADR で行う。
