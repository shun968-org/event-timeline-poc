# ADR-0002: PoC は DB を使わず、静的 JSON を Cloudflare Pages で認証なしに公開する

- ステータス: 採用
- 日付: 2026-10-12
- 関連: Notion 要件定義(REQ-001〜REQ-020, 非機能要件「性能」「セキュリティ」「可用性」「コスト」)、ADR-0001、基本設計「システム構成」

## コンテキスト

PoC で扱うのは、検証シナリオに沿って作った決め打ちの合成データだけで、画面から書き込むことは無い。
1データセットは最大1万件、全体で最大10万件。
このデモ画面を X などの SNS や Qiita・Zenn などの記事で URL を公開し、不特定多数に触ってもらう。
そのため、利用者のアカウント発行・管理はしたくない(手作業はもちろん、人数の上限も避けたい)。
アクセスが急に増えても課金が発生してはならず、できれば止まらないことが望ましい。
開発は devContainer 内で行い、外向き通信は許可ドメインだけに制限している。公開先の認証情報はコンテナに置かない。

### 検討した選択肢

| 案 | 却下理由 |
|---|---|
| DB に取り込み、API で検索する | 決め打ちのデータを見せるだけなら、DB と API の構築・運用・費用に見合わない |
| AWS(S3 + CloudFront)に公開 | この規模ならほぼ無料だが、無料枠を超えると課金される。上限で止める仕組みが無く、「大量アクセスでも課金されない」を保証できない |
| Cloudflare Access で利用者を制限 | 無料は50人まで。不特定多数への公開に合わない |
| 自己登録のアカウント(Supabase Auth など) | 誰でも登録できるなら実質的に公開と同じで、守れるものが増えないのに、認証サービスの上限・管理だけが増える |
| 合言葉(Pages Functions での Basic 認証、合言葉入り URL) | アカウントは不要だが、URL を公開する以上は合言葉も公開される。関数の呼び出しに1日10万回の上限があり、大量アクセスでその日は表示できなくなる |
| Parquet + ブラウザ内の DuckDB-WASM | 1データセット1万件には過剰で、画面が重くなる(WASM が数 MB) |

## 決定

**PoC では DB・API・認証を使わない。取り込み CLI が情報源のファイルからデータセットごとの静的 JSON を作り、画面はその JSON を読んで、絞り込み・検索をブラウザ内で行う。画面と JSON は Cloudflare Pages の無料プランに静的ファイルとしてだけ置き、誰でも見られる形で公開する。**

判断の根拠:

1. **課金が発生しない。** Cloudflare Pages の静的ファイルの配信は無料プランで無制限。Pages Functions などの関数を使わないので、呼び出し回数の上限にも当たらない。
2. **大量アクセスでも止まらない。** Cloudflare の CDN が配信し、DDoS 対策も無料プランに含まれる。
3. **アカウントの管理が要らない。** URL を伝えるだけで誰でも使え、人数の上限も無い。
4. **部品が最小で、検索処理が1系統で済む。** ローカルで確かめた動きと、公開した動きが同じになる。

## 結果

- 誰でも見られるので、扱うのは合成データだけに限り、画面とデータに架空のデータであることを明示する(REQ-013)。公開するファイルに、合成データ以外のもの(内部の情報・認証情報など)を含めない。
- Cloudflare は無料プランのまま使い、有料プランには上げない。上げると従量課金になりうる。
- アクセス解析は Cloudflare Web Analytics(無料、Cookie を使わない)を使う。利用者の個人情報は集めない。
- 感想は GitHub Discussions で受け付ける。画面に書き込み機能を持たないので、DB は引き続き要らない。
- デプロイは GitHub Actions から、Pages の編集だけができる Cloudflare の API トークンで行う。devContainer に Cloudflare の認証情報を置かず、ファイアウォールの許可ドメインも増やさない。
- 画面のデータの読み方を「データソース」として抽象化し、PoC 後に API を足す場合は実装を追加して切り替える。
- 1データセットが大きくなると、最初の読み込みに時間がかかる。最大1万件の範囲では問題にならない想定で、Cloudflare の自動圧縮に頼る。Pages の1ファイルあたりのサイズ上限(25 MiB とされる)を超えないことを書き出し時に検査する。
